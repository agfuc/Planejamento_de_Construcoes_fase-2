Servico.hasMany(Solicitacao, { foreignKey: 'servico_id', onDelete: 'RESTRICT' });
Solicitacao.belongsTo(Servico, { foreignKey: 'servico_id', as: 'servico' });

Servico.hasMany(Noticia, { foreignKey: 'servico_id', onDelete: 'SET NULL' });
Noticia.belongsTo(Servico, { foreignKey: 'servico_id', as: 'servico' });

Servico.hasMany(Evento, { foreignKey: 'servico_id', onDelete: 'SET NULL' });
Evento.belongsTo(Servico, { foreignKey: 'servico_id', as: 'servico' });

Como explicar

  • PK: cada tabela tem um id com primaryKey: true e autoIncrement: true.
  • FK: o campo servico_id tem references: { model: 'servicos', key: 'id' }. É isso que cria a restrição no PostgreSQL.
  • JOIN: com include: [{ model: Servico, as: 'servico' }], a notícia volta com o serviço dentro do JSON.
  • Criação das tabelas: o sequelize.sync({ alter: true }) cria e ajusta as tabelas quando a API inicia.
  • Carga inicial: o seed.js insere primeiro os serviços (tabela pai) e depois as tabelas filhas, que usam o ID deles.
